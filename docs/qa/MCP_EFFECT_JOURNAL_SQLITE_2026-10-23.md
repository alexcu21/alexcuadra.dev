# Protocolo persistente de efectos — ensayo SQLite

Incremento experimental separado: `effect-journal.php`, sin hooks, plugin, abilities, cron o conexión WP.54 comprobaciones con SQLite real y39 regresiones sintéticas del writer correctas; lints PHP y diff whitespace correctos. ZIPrc.2 conserva su hash; lab0.5 y plugin instalado sin cambios.

Se comprueba commit atómico de contenido/aprobación de fixture, evento/recibo e intención; otro lector no observa filas no confirmadas. Una excepción antes de COMMIT y un trigger que rechaza la inserción de intención revierten también contenido/aprobación/recibo. Un replay no reescribe la fuente y mantiene el recibo. Dos procesos compiten por el mismo lease: uno obtiene el derecho, el otro no consume intento. No hay transacción abierta durante el consumidor externo. Lease caducado permite retomar; token anterior no puede confirmar sobre otro worker.

Procesos reales terminan con exit73 antes y después de una invalidación simulada. La intención/lease persisten. El segundo caso repite intencionadamente la invalidación al retomar: entrega al menos una vez, nunca exactamente una vez. Misma clave lógica en reintentos; source no se vuelve a escribir. Excepción, resultado incierto o resultado mal tipado no cuentan como éxito ni revierten contenido. Backoff limitado y8 intentos; último fallo o última muerte sin acknowledgment requieren atención. Recuperación usa un evento independiente y conserva el original.

**Límites:** fixture SQLite, sin WordPress/MariaDB/ACF/Polylang/LiteSpeed real. No se conecta este journal al source writer: las dos conexiones no serían atómicas. Falta portarlo a la misma conexión MariaDB con esquema estricto, coordinar la aprobación real y diferir la callback LiteSpeed auditada con restauración en finally. Accepted solo representa aceptación de la API simulada, no invalidez de todas las cachés. Una llamada externa lenta puede sobrevivir a su lease; fencing protege SQL, no la API. Detalles y contrato de callbacks internos en el README del experimento.

Almacenamiento local:35GiB libres al inicio; pequeños archivos y base SQLite temporal sintética. La prueba elimina únicamente su propio archivo temporal; conserva respaldos y laboratorios. Sin Docker, dependencias, descargas, SSH, cambios CMS/Workers/contacto, scopes o nuevos grants. No se repiten suites del paquete instalado porque no se ha modificado.
